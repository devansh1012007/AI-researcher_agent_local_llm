## 1. What changed

File: `src/research_engine/providers/embeddings/base.py`

1. Added import `from research_engine.core.http_policy import EgressPolicy` and `from urllib.parse import urlparse`.
2. Added module-level helper `_host_of(base_url: str) -> str` that extracts the host via `urlparse(base_url).hostname` and fails closed (raises `RuntimeError`) when the host cannot be parsed — no silent network call on an unparseable URL.
3. `OllamaEmbeddingProvider.__init__` gained `policy: EgressPolicy | None = None`, stored as `self.policy`.
4. `OpenAICompatibleEmbeddingProvider.__init__` gained `policy: EgressPolicy | None = None`, stored as `self.policy`.
5. All four `httpx` call sites now extract the host and call `self.policy.require(host, "...")` when `self.policy is not None`, **before** the network request:
   - `OllamaEmbeddingProvider.embed` — `httpx.post .../api/embeddings` → `require(host, "ollama embed")`
   - `OllamaEmbeddingProvider.is_available` — `httpx.get .../api/tags` → `require(host, "ollama embed")`
   - `OpenAICompatibleEmbeddingProvider.embed` — `httpx.post .../embeddings` → `require(host, "openai embed")`
   - `OpenAICompatibleEmbeddingProvider.is_available` — `httpx.get self.base_url` → `require(host, "openai embed")`

When `self.policy is None` the check is skipped, so existing constructors without `policy` keep working unchanged. Under `EgressPolicy("LOCAL_ONLY")`, any non-loopback host raises `RuntimeError` before the network call (fail-closed).

## 2. Root cause

Embedding providers issued outbound `httpx` requests with no egress-policy consultation. Under `LOCAL_ONLY` a provider could silently call a non-loopback ollama/openai-compatible host, violating the C09 egress requirement. Fix: enforce `policy.require(host)` at every outbound call site, fail-closed, at the source (the provider), not via a wrapper.
