## 3. Root cause

`_guard(event, args)` read `_ALLOWED_WRITE_ROOT` (a module global populated from `os.environ.get` at line 37 of the inlined string) at call time. Because the guard source ran as Python code in the same child process as the user's `exec()`d code, user code could execute `globals()["_ALLOWED_WRITE_ROOT"] = "/tmp"` before any write, and the next `_guard` invocation would use the rebound value, escaping the experiment workdir. The default-argument binding that would have immunized the root was never used — the values were re-read from a mutable module global on every call.

## 4. Changes made

Only the two files in the write-set.

### 4.1 `src/research_engine/experiments/_sandbox_guard.py` (NEW)

Dedicated guard module. Captures `GAR_EXPERIMENT_WORKDIR` / `GAR_EXPERIMENT_NETWORK` once at module import into module-level `_ROOT` / `_DENY_NET`, then binds them as default argument values:

```python
_ROOT = _os.environ.get("GAR_EXPERIMENT_WORKDIR", "")
_DENY_NET = _os.environ.get("GAR_EXPERIMENT_NETWORK", "") != "1"

def _guard(event, args, _root=_ROOT, _deny_net=_DENY_NET):
```

Default argument values are evaluated at function definition time (module import in the child process) and stored in `_guard.__defaults__`. User code executed via `exec()` can rebind module globals but cannot rebind `_guard.__defaults__`, so `_root` / `_deny_net` are fixed for the lifetime of the child. The guard behavior is unchanged from the inlined version: denies `socket.connect`/`getaddrinfo`/`bind` when `_deny_net`, denies `subprocess.Popen`, denies file writes outside `_root`, allows reads/imports.

### 4.2 `src/research_engine/experiments/runner.py`

- Removed the inlined `_SANDBOX_GUARD` source string (lines 33-68).
- Added `from research_engine.experiments._sandbox_guard import _guard` (declares the dependency; the child installs the hook).
- The `python -I -c` child command now installs the guard from the dedicated module:
  ```
  from research_engine.experiments._sandbox_guard import _guard
  import sys as _sys
  _sys.addaudithook(_guard)
  <runner template>
  ```
  The child imports `_sandbox_guard` after `GAR_EXPERIMENT_WORKDIR`/`GAR_EXPERIMENT_NETWORK` are set in `child_env`, so the bound defaults reflect the per-experiment workdir and network setting.

## 6. Alternatives considered and rejected

- **Keep `_ALLOWED_WRITE_ROOT` as a module global but guard the rebind**: rejected — any call-time read of a mutable global is rebindable by exec'd code in the same process; does not fix the root cause (band-aid).
- **Read env var inside `_guard` on every call**: rejected — same rebindability issue; env re-read is call-time, not definition-time.
- **Pass `_root`/`_deny_net` as keyword args from runner**: rejected — runner runs in the parent process; the guard runs in the child via `sys.addaudithook`, and the values must be bound where the guard is defined/imported (the child) from the child's env.
- **Move only the logic, keep `_SANDBOX_GUARD` string**: rejected — the brief requires removing the inlined string and importing `_guard` from `_sandbox_guard`; a string still re-evaluates `_os.environ.get` at call time unless the defaults are bound.
