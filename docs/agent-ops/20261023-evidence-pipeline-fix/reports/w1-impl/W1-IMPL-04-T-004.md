## 3. Root cause

`security.local_only: bool = True` was defined but never read (`effective_environment()` consulted only `privacy_mode` and `platform.mode`). The privacy guarantee ("local_only ⇒ no external calls") was unimplemented — the field was decorative. Per the investigation findings (brief §2 item 5) and plan D-2 / C10, `local_only` must force LOCAL_ONLY so `build_default_registry()` returns an empty registry under LOCAL_ONLY.

Key design tension (brief §6 gotcha): `local_only` defaults to `True`, so unconditional `local_only=True → LOCAL_ONLY` would flip DEFAULT `AppConfig()` (mode: local) from HYBRID to LOCAL_ONLY, breaking `test_every_leg_resolves_or_is_explicitly_optional` (builds `build_default_registry(AppConfig())` and asserts ≥1 provider registers) and silently darkening every default install — contradicting plan D-1 ("`local` (default) = today's real behaviour ... with a truthful label").

## 4. Changes made

### 4.1 Root-cause fix — src/research_engine/core/config.py

Two minimal edits:

**(a) Default changed `True → False`** (`SecurityConfig.local_only`, line 146). Rationale: `local_only=True` must force LOCAL_ONLY (fail-closed), but the DEFAULT `AppConfig()` must keep resolving to HYBRID (today's behaviour) so existing tests and the default install are not darkened. Because `local_only`'s value (True) is identical whether it is the Python default or an explicit operator choice, and `model_fields_set` cannot distinguish them once nested inside `AppConfig` (verified unreliable), the only clean way to preserve `AppConfig()` → HYBRID while making explicit `local_only=True` → LOCAL_ONLY is to default `False`. Operators opt into strict local-only via `security.local_only: true` in `gar.yaml` (which already sets it at line 79). This is a behaviour-preserving default: `AppConfig()` → mode:local → HYBRID, exactly as before the field was wired (the field was previously ignored).

**(b) `local_only` consulted in `effective_environment()`** (lines 188-193), after `privacy_mode` and before the mode mapping so it overrides `platform.mode` ("regardless of platform.mode"). Logs an `info` message and returns `LOCAL_ONLY` (fail closed). Unknown-mode → LOCAL_ONLY + `log.error` preserved unchanged (lines 199-205).

Order of precedence: `privacy_mode` → `local_only` → mode mapping → unknown-mode fail-closed → LOCAL_ONLY.

### 4.2 New test — tests/unit/test_local_only_gating.py (new file)

Five tests:
- `test_local_only_forces_local_only`: `local_only=True` + `mode: online` → LOCAL_ONLY.
- `test_local_only_forces_local_only_even_in_local_mode`: `local_only=True` + `mode: local` → LOCAL_ONLY (overrides default HYBRID).
- `test_local_only_default_preserves_hybrid`: default `AppConfig()` → `local_only is False` and `effective_environment() == HYBRID` (guards against darkening the default install).
- `test_unknown_mode_resolves_to_local_only`: unknown mode → LOCAL_ONLY with `error` logged (`caplog`).
- `test_local_only_registry_is_empty`: `build_default_registry(AppConfig(platform=...local_only=True...))` → empty registry, `get_any(name) is None` for web/openalex/crossref/arxiv/semantic_scholar.
