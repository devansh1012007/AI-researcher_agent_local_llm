## 3. Root cause

`fetching.py:80` used `httpx.Client(follow_redirects=True, ...)`. httpx follows 301/302/307/308 redirects automatically, so the `Location` header's host is never consulted by `EgressPolicy`. A pre-flight check on the initial URL is bypassed by a single redirect hop to an external host. Root cause: auto-redirects + no per-hop host validation. Fix: disable auto-redirects, validate the initial host before any network call, and on each 3xx response validate the `Location` host before manually issuing the next request.

## 4. Changes made

### 4.1 src/research_engine/pipeline/fetching.py

- Added imports: `from urllib.parse import urljoin, urlparse` and `from research_engine.core.http_policy import build_egress_policy`.
- `__init__`: added `self.policy = build_egress_policy(cfg)` (after existing fields; constructor signature `__init__(self, cfg, cache=None, transport=None)` unchanged).
- Added class constant `MAX_REDIRECTS = 10` to bound the redirect loop.
- `_do_fetch`: replaced `follow_redirects=True` with `follow_redirects=False`. Before the first `client.stream("GET", url)`: `self.policy.require(urlparse(url).hostname or "", "document fetch")` — validates the initial host before any network call.
- Manual redirect loop: `for _ in range(self.MAX_REDIRECTS):` issues `client.stream("GET", current_url)`. On 301/302/307/308: extracts `location` header, resolves via `urljoin(current_url, location)`, calls `self.policy.require(urlparse(redirect_url).hostname or "", "redirect")`, then sets `current_url = redirect_url` and continues (each hop re-validated — a 302 to loopback then 302 to external is caught at the second hop). On non-redirect: reads body and returns `FetchedContent`. Loop exhaustion or a redirect without `Location` returns `FetchedContent(url=url, status=0, error="too many redirects")`.
- Existing `httpx.HTTPStatusError`/`httpx.HTTPError` handling preserved unchanged.

Decision: raise `RuntimeError` (via `EgressPolicy.require`) BEFORE any network call and before each redirect hop, so under LOCAL_ONLY a non-loopback host fails fast with no `httpx` request issued. `follow_redirects=False` guarantees httpx never follows a hop without our explicit validation. `MAX_REDIRECTS=10` bounds the loop (no unbounded loop, per standing orders §7).

## 7. Alternatives considered and rejected

- Keep `follow_redirects=True` + single pre-flight check on initial URL: rejected — a 302 to an external host escapes the pre-flight check (the exact vulnerability this task fixes). Manual per-hop validation is required per brief §3/#5/#6.
- Gate only at `DocumentFetcher` construction: rejected — construction-time gating does not cover request-time redirects; the `Location` host is only knowable after the first response.
- `httpx.Client(event_hooks=...)` to inspect responses: rejected — more complex, less explicit; the manual loop with `follow_redirects=False` is the clearest, most auditable per-hop validation.
- Unbounded `while` loop on redirects: rejected — standing orders §7 forbids unbounded loops; `MAX_REDIRECTS = 10` bounds it.
