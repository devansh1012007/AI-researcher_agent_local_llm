## 3. Root cause

`build_provider()` is the single funnel for LLM provider construction but has no `policy` parameter, so `ModelRouter` cannot convey an `EgressPolicy` (built from `app_cfg.platform.effective_environment()`) to constructed providers. Without this, LLM providers constructed through `ModelRouter` cannot enforce LOCAL_ONLY egress at request time — C09's request-time enforcement gap for the LLM tier.

Two implementation questions resolved:

(a) How `build_provider` delivers `policy` to providers: constructor injection `cls(cfg, policy=policy)` was considered and REJECTED. `MockProvider` (in `llm/base.py`, outside my write-set, owned by no W2 agent) has `__init__(self, cfg=None, handler=None)` and does NOT accept a `policy` kwarg. `build_provider` falls back to `MockProvider` for unknown providers and registers `"mock": MockProvider` in `_PROVIDERS`, so `cls(cfg, policy=None)` would raise `TypeError` — breaking `build_provider(cfg)`, the existing caller, and violating acceptance criterion #4. Since I may not touch `base.py`, constructor injection is not safe.

(b) Chosen approach: `build_provider` accepts `policy`, constructs the provider via `cls(cfg)` (or `MockProvider(cfg)` for the fallback), and — only when `policy is not None` — stores it on the instance as `provider.policy = policy`. Per brief item 23, `build_provider` "just needs to accept and store the policy." This delivers the policy to every constructed provider (including `MockProvider`, which gains the attribute dynamically), keeps `build_provider(cfg)` with `policy=None` completely unchanged (no new attribute, no constructor kwarg), and satisfies acceptance #4. `ModelRouter` always passes a resolved `EgressPolicy` (non-None from `build_egress_policy`), so providers built through the router always receive the policy.

W2-IMPL-09's providers (`ollama`, `openai_compatible`, `llama_cpp` via inheritance) already accept `policy` in their constructors and store `self.policy = policy`; when built through the router, `build_provider` overwrites that default `None` with the resolved policy via attribute assignment — end state identical to constructor injection, no conflict.

## 6. Alternatives considered and rejected

- Constructor injection `cls(cfg, policy=policy)`: rejected — `MockProvider.__init__(self, cfg=None, handler=None)` (llm/base.py, outside write-set) rejects the `policy` kwarg, so `build_provider(cfg)` for the mock/unknown-provider path would raise `TypeError`. Violates acceptance #4. (Post-construction assignment is functionally equivalent for enforcement: providers read `self.policy` at request time.)

- Call `policy.require(host)` inside `build_provider`: rejected — brief item 23 explicitly assigns request-time enforcement to provider classes (they know the host they call); `build_provider` only transports the policy.
